# 1.4.1 Image Download Implementation Plan

> Execute the approved plan inline in this task, with verification after each component.

**Goal:** Preserve actionable image download failures and retry existing URLs without repeating generation.

**Architecture:** GptImageDiagnostics owns serializable, sanitized diagnostics. GptImageDownload owns bounded GET attempts and cancellation. GptImageResponse parses and identifies images; MaibaoApi integrates the helpers and persists diagnostics in n8n errors.

**Tech Stack:** TypeScript, n8n HTTP helpers, Node test runner, release-it.

## Global constraints

- One download attempt: 20,000 ms; whole download stage including waits: 80,000 ms.
- Initial attempt plus at most three retries, always same URL; no generation POST retries inside this logic.
- Preserve default failure semantics and existing Base64/Binary output.
- Do not disclose signed URLs in messages/logs; retain them in execution details for recovery.
- No paid generation tests. GitHub publication only; npm.publish stays false.

## Task 1: Download and diagnostics

Files: create nodes/MaibaoApi/GptImageDiagnostics.ts, nodes/MaibaoApi/GptImageDownload.ts, test/gpt-image-download.test.js.

Interfaces: downloadGptImage(url, request, options) returns buffer and diagnostics; GptImageError carries a safe message and plain diagnostics. Request consumes timeout and abortSignal, returns body/statusCode/headers.

- [ ] Write deterministic tests with an injected monotonic clock/sleep: three timed-out attempts plus waits leave less than 20 seconds for the fourth attempt; stop at 80 seconds.
- [ ] Test retryable network codes and 408/429/500/502/503/504, Retry-After, non-retryable 403, cancellation during requests/waits, and a transport that ignores timeout.
- [ ] Implement deadline enforcement with AbortController and a bounded Promise race; retain only allowlisted diagnostic fields from transport errors.
- [ ] Run npm run build and node --test test/gpt-image-download.test.js.
